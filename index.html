Bug bounty & vulnerability research

I hunt for real, exploitable vulnerabilities in production applications through authorized bug-bounty programs on platforms like HackerOne, Bugcrowd, Intigriti and YesWeHack. Every target I touch is in scope and covered by the program's rules — I test only what I'm allowed to, use a single non-destructive proof-of-concept, and disclose responsibly through the program so the company can fix the issue.

What I look for

Broken access control and IDOR/BOLA, authentication and OAuth/SSO flaws leading to account takeover, business-logic abuse, and injection. I focus on authenticated and mobile-backed surfaces, where fewer people look and findings are less likely to be duplicates.

How I work

Recon and attack-surface mapping first, then hands-on testing against web APIs and Android apps — decrypting app traffic with a rooted emulator, Frida and mitmproxy to reach the API underneath, and reasoning about each endpoint's authorization model rather than running a scanner over it.

The report

Each finding becomes a written report: affected asset, root cause and CWE, a minimal step-by-step proof of concept, impact, and a concrete remediation plan. The goal is a report a triager can reproduce in minutes and an engineer can fix without a second round of questions.

Some of this work is under private programs and NDAs, so specific targets and live findings aren't published here. The public tooling below — apk-drill and the recon pipelines built on it — is the part of that workflow I can share.

Bet-Terminal

Data pipeline · Web app

Why I built it I started betting on sports for profit at the start of 2026. Comparing odds meant opening each bookmaker's site by hand and checking game by game, which took a long time. So I built the whole comparison system myself. It has saved me a lot of time and made me a good amount of money.

An arbitrage finder for sports betting. It scrapes odds from 15 Nordic-facing bookmakers every few minutes, matches the same fixture across books against a canonical league and team registry, and flags arbitrages: sets of bets on every outcome, at different books, that guarantee a profit. Each leg is also compared with a sharp reference book (Pinnacle, or Veikkaus for Finnish leagues) to show how much value it holds on its own.

  • Football, ice hockey, tennis, basketball, darts and CS2: 1X2, Asian handicap, totals, team totals, BTTS, corners, cards and first-half markets
  • Stake split per leg and one-click links to each book's bet page; bet history and settlement are tracked per user
  • Desktop terminal UI and a mobile layout, plus a per-user Telegram alert bot
  • Runs 24/7 on a home server as an 8-service Docker Compose stack (scraper, matcher, settler, web, bots, PostgreSQL, backups)

Python · FastAPI · PostgreSQL · Docker Compose · JavaScript · Telegram Bot API

apk-drill

Security tooling

Why I built it Some Android apps ship with hard-coded secrets, and those can be reported to public bug-bounty programs for rewards. I built this pipeline to automate looking through the APKs.

A single-machine pipeline that searches Android APKs for leaked secrets during authorized bug-bounty work. It downloads each APK, extracts it, scans it with TruffleHog (which checks whether found keys are still live), and writes a Markdown report with a remediation plan. Files are deleted after each package, and an error in one package doesn't stop the run.

scope → apkeep → extract → trufflehog → results.jsonl → report.md
  • Builds package lists from HackerOne, Bugcrowd, Intigriti and YesWeHack scopes, keeping only in-scope Android assets
  • Additional modules: API surface mapping, CORS and authorization probes, JWT analysis, SDK→CVE mapping, blast-radius estimates for leaked keys
  • Runs daily under cron on a home server; watches for app updates and new programs

Python · Bash · TruffleHog · apkeep · cron

Anki text-to-speech

Language learning

Why I built it I was learning Japanese with Anki and making my own flashcards, but they had no audio. Hearing words spoken is an important step in learning a language, so I wrote a simple script for myself that adds it.

Adds spoken audio to Anki flashcards. You choose a deck; the script reads each note's Word or Sentence through AnkiConnect, generates speech with gTTS, saves it to the collection's media folder and fills in the card's Audio field. It started as a CSV-driven script and now has a desktop GUI.

  • Japanese, Mandarin, Korean, Spanish, French, Swedish, Arabic, English
  • Talks to Anki directly through AnkiConnect; no CSV exports needed
  • customtkinter GUI, so you don't have to edit the source to use it

Python · gTTS · AnkiConnect · customtkinter
